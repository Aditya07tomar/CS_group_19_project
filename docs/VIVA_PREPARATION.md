# Viva preparation

## SQL injection

1. **What is SQL injection?** Input changing SQL syntax. 2. **Why does bypass work?** A comment removes the password predicate. 3. **Why prepared statements?** Values are not parsed as SQL. 4. **Why validate input too?** It narrows accepted data but is not a substitute. 5. **Why least privilege?** It reduces database impact. 6. **Why generic errors?** They reduce information leakage. 7. **What does the secure payload do?** It becomes a literal value. 8. **Why fictional data?** The lab needs no real secrets. 9. **What is parameter binding?** Separating query grammar from values. 10. **What is a predicate?** A WHERE condition. 11. **Why comments matter?** They can remove remaining query text. 12. **Why use SQLite here?** Portable local seeded database. 13. **Can escaping replace binding?** No. 14. **What is an allow-list?** Explicit permitted input forms. 15. **What is query shape?** SQL structure before values. 16. **How verify mitigation?** Repeat exact payload. 17. **Normal functionality after fix?** Valid credentials still work. 18. **What is attack surface?** Inputs reaching SQL. 19. **What is the root cause?** String concatenation. 20. **What is the key mitigation?** Parameterized queries.

## OS command injection

1. **What is command injection?** Input changes a shell command. 2. **Why semicolon?** Shell command separator. 3. **What is in-band injection?** Output returns in the response. 4. **Why use `whoami` here?** It is a controlled, harmless proof of command execution. 5. **Why timeout?** It prevents hung child processes. 6. **What is `exec`?** It runs a command string through a shell. 7. **What is `execFile`?** It runs a fixed executable with an argument vector. 8. **What is an argument vector?** Separate executable and values. 9. **Why avoid a shell?** Metacharacters lose special meaning. 10. **Why host allow-list?** It limits valid targets. 11. **Why localhost only?** The lab never scans networks. 12. **Why output limit?** It bounds resource use. 13. **Why least privilege?** It limits process power. 14. **Can validation alone solve it?** No, avoid shell interpretation too. 15. **Why ping?** It is a familiar benign utility. 16. **What proves the attack?** The returned `whoami` output. 17. **Why not root?** It magnifies harm. 18. **How test secure route?** Submit the exact same payload. 19. **What is shell interpretation?** Parsing special characters before execution. 20. **Root cause?** Direct command string construction.

## XSS

1. **What is XSS?** Untrusted content executes in a page. 2. **Stored versus reflected?** Persisted content versus immediate response reflection. 3. **Why innerHTML dangerous?** It parses markup. 4. **Safe sink?** `textContent`. 5. **What is output encoding?** Rendering data without syntax meaning. 6. **Why context-aware?** HTML, URL, JS contexts differ. 7. **Why harmless alert?** Demonstrates execution without data theft. 8. **What is a DOM sink?** API receiving content. 9. **Why reset comments?** Repeatable demo state. 10. **Can CSP replace encoding?** No, it is defence in depth. 11. **What is sanitization?** Removing unsafe constructs for legitimate HTML. 12. **Why use sanitizer carefully?** Configuration mistakes matter. 13. **What does HttpOnly help?** It limits script cookie access, not XSS. 14. **Does it prevent XSS?** No. 15. **Why framework escaping?** Safe default rendering. 16. **How prove mitigation?** Payload appears literally. 17. **What is an event handler?** Attribute that can execute JS. 18. **Why avoid untrusted templates?** They may execute expressions. 19. **Root cause?** HTML interpretation of data. 20. **Normal functionality?** Plain text comments/search works.

## CSRF

1. **What is CSRF?** Cross-site request using ambient authentication. 2. **Why does a cookie matter?** Browser attaches it automatically. 3. **Why is state-changing GET unsafe?** Images and links can trigger it. 4. **Synchronizer token?** Secret tied to a session and submitted by legitimate UI. 5. **Why attacker lacks it?** Same-origin policy prevents reading it. 6. **Why separate localhost origins?** Browser cross-site behavior needs different hostnames. 7. **Why HTTPS?** `SameSite=None` requires Secure. 8. **What is SameSite?** Cookie cross-site sending policy. 9. **Why token validation?** Cookie presence alone is insufficient. 10. **Why use a mock profile?** No real financial or personal action occurs. 11. **Why re-authenticate?** Extra protection for sensitive actions. 12. **Can SameSite replace tokens?** Not universally. 13. **Why bind token to session?** Prevent token reuse across sessions. 14. **What does 403 indicate?** Protected request rejected. 15. **What proves exploit?** Profile changes after attacker page. 16. **What proves mitigation?** Missing token leaves profile unchanged. 17. **Why local certificate?** It enables realistic cookie settings. 18. **What is the root cause?** No proof of user intent. 19. **What does the secure route validate?** The session-bound token. 20. **What should a secure application avoid?** State-changing GET requests.
